# PHVD — Android and web

## Web app — LIVE

**https://nncceducation-cpu.github.io/PHVD/app/**

Verified working: disclaimer gate loads, VI 16.2 at PMA 28 correctly returns
**High Risk** with the trigger `VI > 97th% + 4mm`, the Brouwer curve plots, and the
management plan and References render.

- Installable (PWA manifest + icons) — "Add to Home Screen" on any phone
- **Works offline.** A service worker caches the shell. A NICU is exactly the sort of
  place where the wifi drops, so the app should not depend on it.
- Same code as the iOS/Android builds. No accounts, no network calls, no analytics.
- Source in `docs/app/`, generated by `npm run build:web`.

The privacy-policy page at the root URL is untouched and still live — Apple is
reviewing against it. It now links to the app.

## Android — built and signed, NOT yet on Play

`.aab` (for Play) and `.apk` (for sideloading) are built, signed, and signature-verified.
Download them from the **phvd-android** artifact:

https://github.com/nncceducation-cpu/PHVD/actions/workflows/android-release.yml

To rebuild: Actions → "Android build" → Run workflow. Bump the **version code** every
time; Play rejects a reused one.

### What had to change from stock Capacitor

| | |
|---|---|
| Capacitor 6 ships **targetSdk 34** | Play rejects new apps below **API 35** today, and requires **36 from 31 Aug 2026** |
| compileSdk 35 needs **AGP >= 8.6**; Capacitor ships 8.2.1 | AGP -> 8.7.3, Gradle -> 8.9 |
| The stock release build is **unsigned** | Signing config injected; CI now *fails* if the .aab has no signature block |

All of this lives in `scripts/patch-android.py`, which re-applies it on every CI run
(`android/` is gitignored and regenerated, same as `ios/`). **Bump `TARGET_SDK` to 36
before 31 Aug 2026.**

### The keystore

`certs/phvd-release.keystore` — 4096-bit RSA, valid 10,000 days. Gitignored.

**Back this up somewhere off your laptop.** If you lose it you can never update the app
on Play under this listing. Google will not re-key you. The only remedy is a new listing
under a new package name, losing every install and review.

## What is blocking the Play upload

Play Console says: *"Complete account verifications to create new apps."* The app record
cannot be created — by me or by you — until Google clears the account:

1. **Identity verification** — documents uploaded, Google is reviewing. Takes days. Nothing to do.
2. **Verify access to an Android device** — sign in to the Play Console app on a real
   Android phone. **Only you can do this**, and it is usually the long pole.
3. **Verify contact phone number** — gated behind (1).

Once the account clears, everything else is ready: the signed bundle, the icons, the
listing copy (reuse `APP_STORE_LISTING.md`), the privacy policy URL, and the answers to
Play's Data Safety form (nothing collected — same as Apple's "Data Not Collected").

### When Play asks the health-app questions

Answer consistently with what we told Apple, because the app is the same:

- **Health app?** Yes, in the Medical category.
- **Regulated medical device?** **No.** Not registered with the FDA, Health Canada, or
  any other regulator.
- **Data Safety: no data collected, no data shared.** True — no network calls at all.
